# Agent Definitions

## Phase 1 에이전트 (병렬 실행)

### Agent 1: doc-updater (문서 업데이트 탐색)

**역할**: 프로젝트 문서 중 업데이트가 필요한 곳을 찾는다.

**분석 대상**:
- CLAUDE.md — 프로젝트 설명, 현재 상태, 컨벤션 등이 변경 내용과 맞는지
- README.md — 새로운 기능이나 설정이 반영되어야 하는지
- 기타 문서 파일 — 변경된 코드와 관련된 문서가 있는지

**출력 형식**:
```
📝 문서 업데이트 제안
• [파일명]: [업데이트 내용] (우선순위: 높음/중간/낮음)
```

### Agent 2: automation-scout (자동화 기회 탐색)

**역할**: 세션에서 반복된 패턴을 찾아 자동화를 제안한다.

**분석 대상**:
- 반복적으로 실행한 명령어 패턴
- 수동으로 처리한 작업 중 스킬/스크립트로 만들 수 있는 것
- 기존 스킬로 대체할 수 있었던 작업

**출력 형식**:
```
⚡ 자동화 제안
• [패턴]: [자동화 방법] (절약 효과: 높음/중간/낮음)
```

### Agent 3: learning-extractor (학습 내용 추출)

**역할**: 세션에서 배운 것을 정리한다.

**분석 대상**:
- 새로 알게 된 도구, 명령어, API, 패턴
- 해결한 문제와 그 해결 방법
- 시행착오에서 얻은 교훈

**출력 형식**:
```
🎓 오늘 배운 것
• [주제]: [핵심 내용]
```

### Agent 4: followup-suggester (후속 작업 제안)

**역할**: 다음 세션에서 이어서 할 작업을 제안한다.

**분석 대상**:
- 이번 세션에서 완료하지 못한 작업
- TODO/FIXME 주석으로 남긴 것
- 자연스럽게 이어지는 다음 단계

**출력 형식**:
```
📌 다음에 할 일
• [작업]: [이유] (우선순위: 높음/중간/낮음)
```

## Phase 2 에이전트 (순차 실행)

### Agent: duplicate-checker (중복 검증)

**역할**: Phase 1에서 나온 모든 제안을 검토하여 중복을 처리한다.

**왜 필요한가**: 4개 에이전트가 독립적으로 분석하므로, 같은 내용을 다른 관점에서 제안할 수 있다.
- 예: doc-updater가 "CLAUDE.md 업데이트 필요"를 제안하고, followup-suggester도 "CLAUDE.md 수정"을 제안하면 중복이다.

**검증 규칙**:

1. **완전 중복** → 제거
   - 두 에이전트가 동일한 파일에 동일한 작업을 제안한 경우
   - 하나만 남기고 나머지 제거

2. **부분 중복** → 병합 제안
   - 비슷하지만 관점이 다른 제안 (예: 같은 파일이지만 수정 내용이 다름)
   - 하나로 합칠 수 있는 형태로 병합 제안

3. **중복 없음** → 그대로 통과
   - 각 에이전트의 제안이 독립적이면 그대로 유지

**출력 형식**:
```
🔍 중복 검증 결과
─────────────────
• 완전 중복 제거: N건
• 부분 중복 병합: N건
• 최종 제안 수: N건 (원래 N건에서 정리)
```
